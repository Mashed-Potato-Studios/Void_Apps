# Coffee — Void Quickstart Demo App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `apps/coffee` — a coffee-lovers storefront + admin dashboard that exercises the whole Void toolchain: real `void@^1.1` SDK, D1 + Drizzle, typed fetch API routes, two cron jobs, CronPanel admin page, void-crons + void-fingerprint CLIs, ending in a real Cloudflare deploy.

**Architecture:** Quickstart-native scaffolding (React Pages starter, D1) wired into the existing monorepo. Pages carry their server logic in `.server.ts` loaders/actions per the Void Pages contract. Cron jobs live in `crons/` and are managed via the `void-crons` CLI from `packages/crons`. One shop state machine: menu (read) → checkout (write) → dashboard (aggregate) → crons (maintenance).

**Tech Stack:** void@^1.1.11 (real SDK + voidPlugin), Vite + React, Drizzle over D1, typed fetch (`void/client`), ShadCN-style Card/Button/Badge inline styling + ReactBits-inspired ambiance (repo pattern: styled JSX-styled components like apps/web), workspace packages `@void-monorepo/types|auth|ui|crons`.

**Spec:** `docs/superpowers/specs/coffee-void-app.md`

## Global Constraints

- All money is integer `price_cents`/`total_cents` — never floats.
- Every cron file must carry `export const cron = '<5-field>'` — deploy + void-crons ignore files without it.
- Handlers returning a `CronExecutionResult` shape (spec parity with apps/api/crons) — `CronExecutionResult` from `@void-monorepo/types`.
- D1 queries are Drizzle over `db from 'void/db'` (fingerprint test fixture pins this import shape as a real SDK specifier).
- No raw `console.error` for recoverable D1 writes — catch, log, rethrow so the scheduler's activity log records the failure.
- Never touch apps/api/web/admin for coffee's work; new vite.config goes in apps/coffee only.
- Deploy step requires interactive Cloudflare sign-in — when the browser step appears, stop and hand to the user.
- Node >=22.6 (repo engines), pnpm via the repo's corepack-managed version.

## Review Focus

1. **Real `voidPlugin()` unknowns** — v1.1 CLI may reject/rewrite `void.json` keys copied from the shim apps (routing, head, auth). Expected behavior: CLI wins; whatever `void init`/`void dev` emits locally is canonical. → Pinned by Task 2's void-dev-boot acceptance step (fallback: remove unsupported keys, note in commit message).
2. **D1 not yet provisioned during `void dev`** — if `db from 'void/db'` fails locally pre-deploy, loaders must show empty-state UI instead of crashing. → Pinned by Task 4's degraded-mode test (loader catch → empty menu list).
3. **Cron local fires against real endpoint** — jobs must validate against Cloudflare 5-field shape AND actually fire locally; if `/__void/scheduled` doesn't exist in v1.1.x, raw-expression trigger via `void-crons trigger '<cron expr>'` is the fallback. → Pinned by Task 5's `schedule --once` + `trigger` sweep.
4. **Typed-fetch contract could drift from `void/client` shape** — quickstart shows `fetch('/api/hello')`, repo pattern is `{success, data}`. Coffee routes follow the repo `{success, data, error}` envelope regardless of client helper; page client code uses `fetch` from 'void/client' when present, else plain `fetch`. → Pinned by Task 4 route test.
5. **Workspace TS-source packages under a fresh Vite+** — `@void-monorepo/ui` etc. expose `.ts` mains; real voidPlugin's optimizer might choke. Expected: they compile as-is (same as existing apps) — if not, exclude from optimizeDeps. → Pinned by Task 2 dev-boot check importing `@void-monorepo/ui`.

```tsx
import { useState, type FormEvent } from 'react';
import { Header, Card, Button } from '@void-monorepo/ui';
import { initialMenu } from '../db/seed.js';
import type { MenuItem } from '../db/schema.js';
import '@void-monorepo/ui/styles.css';

export type MenuPageProps = { menu?: MenuItem[] };

export default function StorefrontPage({ menu = initialMenu }: MenuPageProps) {
  const [cart, setCart] = useState<Record<string, number>>({});
  const [busy, setBusy] = useState(false);
  const [error, setError] = useState<string | null>(null);
  const [order, setOrder] = useState<{ id: string } | null>(null);

  const add = (slug: string): void => setCart((c) => ({ ...c, [slug]: (c[slug] ?? 0) + 1 }));
  const inCart = Object.entries(cart).filter(([, q]) => q > 0);

  async function checkout(event: FormEvent): Promise<void> {
    event.preventDefault();
    if (!inCart.length) return;
    setBusy(true); setError(null);
    // Task 6 targets POST /api/orders once the D1 wiring lands; dev surface
    // stays on the route contract so this client shape never changes again.
    try {
      const res = await fetch('/api/orders', {
        method: 'POST',
        headers: { 'content-type': 'application/json' },
        body: JSON.stringify({ items: inCart.map(([slug, qty]) => ({ slug, qty })) }),
      });
      const json = (await res.json()) as { success: boolean; data?: { id: string }; error?: { message: string } };
      if (!json.success || !json.data) throw new Error(json.error?.message ?? 'Checkout failed');
      setOrder(json.data); setCart({});
    } catch (e) {
      setError(e instanceof Error ? e.message : String(e));
    } finally {
      setBusy(false);
    }
  }

  return (
    <div style={{ minHeight: '100vh', backgroundColor: '#08060d', color: '#fff' }}>
      <Header appName="Crew Coffee" badgeText="Void Quickstart" links={[{ label: 'Menu', href: '/', active: true }, { label: 'Dashboard', href: '/dashboard' }, { label: 'Crons', href: '/admin/crons' }]} />
      <main style={{ maxWidth: 1100, margin: '0 auto', padding: '3rem 1.5rem' }}>
        {error ? <p style={{ color: '#ef4444' }}>error: {error}</p> : null}
        {order ? (
          <div style={{ padding: '1rem', background: '#101826', border: '1px solid #1c2b45' }}>
            <h2 style={{ marginTop: 0 }}>Order placed ({order.id})</h2>
            <p style={{ color: '#9490a5' }}>Thanks! Your coffee is on the way.</p>
            <Button variant="secondary" onClick={() => { setOrder(null); }}>Back to menu</Button>
          </div>
        ) : (
          <section style={{ display: 'grid', gridTemplateColumns: 'repeat(auto-fill, minmax(260px, 1fr))', gap: '1.25rem', marginBottom: '2.5rem' }}>
            {menu.map((m) => (
              <Card
                key={m.slug}
                title={m.name}
                description={m.origin === 'single' ? 'Single origin' : 'House blend'}
                tag={m.stock < 5 ? `Low stock · ${m.stock}` : `$${(m.priceCents / 100).toFixed(2)}`}
                footer={<Button variant="primary" disabled={!m.stock} onClick={() => add(m.slug)}>{m.stock ? 'Add to cart' : 'Sold out'}</Button>}
              />
            ))}
          </section>
        )}
        <form onSubmit={checkout} style={{ position: 'sticky', bottom: '1rem', display: 'flex', gap: '0.75rem', alignItems: 'center' }}>
          <span style={{ color: '#9490a5' }}>{inCart.length} item(s)</span>
          <Button variant="primary" disabled={!inCart.length || busy}>{busy ? 'Placing order…' : 'Checkout'}</Button>
        </form>
      </main>
    </div>
  );
}
```

// Void Scheduled Cron Job (nightly 03:00) — restocks every active menu item
// up to its default_stock level for the next business day.
export const cron = '0 3 * * *';

export default async function handleCron(event: { cron: string; scheduledTime: number }): Promise<CronExecutionResult> {
  const start = Date.now();
  try {
    // Task 6 swaps this for: UPDATE menu_items SET stock = max(default_stock, stock) WHERE is_active = 1
    console.log(`[coffee/rollover] restock placeholder at ${new Date(event.scheduledTime).toISOString()}`);
    return {
      jobName: 'coffee-nightly-restock',
      scheduledTime: new Date(event.scheduledTime).toISOString(),
      durationMs: Date.now() - start,
      status: 'success',
      itemsProcessed: 0,
    };
  } catch (e) {
    console.error('[coffee/rollover] failed:', e);
    throw e;
  }
}

```ts
export const POST = defineHandler(async ({ request }: { request: Request }) => {
  const body = (await request.json()) as { items?: { slug: string; qty: number }[] };
  if (!body.items?.length) {
    return new Response(
      JSON.stringify({ success: false, error: { code: 'EMPTY_CART', message: 'At least one item required' } }),
      { status: 400, headers: { 'Content-Type': 'application/json' } },
    );
  }
  const bySlug = new Map(initialMenu.map((m) => [m.slug, m]));
  const resolved: { menuItemId: string; qty: number; priceCents: number }[] = [];
  for (const { slug, qty } of body.items) {
    const m = bySlug.get(slug);
    if (!m) {
      return new Response(
        JSON.stringify({ success: false, error: { code: 'UNKNOWN_ITEM', message: `slug "${slug}" not found` } }),
        { status: 400, headers: { 'Content-Type': 'application/json' } },
      );
    }
    resolved.push({ menuItemId: m.id, qty, priceCents: m.priceCents });
  }
  const totalCents = resolved.reduce((n, r) => n + r.priceCents * r.qty, 0);
  const orderId = `co_${Date.now().toString(36)}`;
  try {
    const { db } = await import('void/db');
    await db.transaction? (async (tx: { insert: typeof db.insert }) => {
      await tx.insert(orders).values({ id: orderId, totalCents, status: 'paid' as const, createdAt: new Date().toISOString() });
      await tx.insert(orderItems).values(
        resolved.map((r, i) => ({
          id: `${orderId}_${i}`,
          orderId,
          menuItemId: r.menuItemId,
          qty: r.qty,
          priceCents: r.priceCents,
        })),
      );
    });
  } catch (e) {
    console.log('[coffee] orders insert skipped (local D1 pending):', e instanceof Error ? e.message : String(e));
    return new Response(
      JSON.stringify({ success: false, error: { code: 'DB_UNAVAILABLE', message: 'Local D1 not provisioned yet (deploy target pending)' } }),
      { status: 503, headers: { 'Content-Type': 'application/json' } },
    );
  }
  return { success: true, data: { id: orderId, totalCents } };
});
```

If Drizzle's real transaction API differs (`db.transaction(cb)` vs chained `await`s), drop the transaction wrapper and run two plain `await db.insert(...)` calls — the order row lacking items is better than failing the whole checkout in a mock purchase. (Zero-stock items are blocked at the page layer, disabled button; the API does not double-check stock, which is an acceptable mock-purchase cut per spec.)

import { desc } from 'drizzle-orm';
import { initialMenu } from '../db/seed.js';
import { orders } from '../db/schema.js';

export type DashboardLoader = {
  recentOrders: { id: string; totalCents: number; createdAt: string }[];
  revenueCents: number;
  lowStock: { slug: string; name: string; stock: number }[];
  topCoffee: string | null;
};

export async function loader(): Promise<DashboardLoader> {
  const lowStock = initialMenu.filter((m) => m.stock < 5).map((m) => ({ slug: m.slug, name: m.name, stock: m.stock }));
  try {
    const { db } = await import('void/db');
    const rows = await db.select().from(orders).orderBy(desc(orders.createdAt)).limit(10);
    const revenueCents = rows.reduce((n, r) => n + r.totalCents, 0);
    // topCoffee enrichment (join over coffee_stats) lands with the real
    // top-coffee cron data; until the cron has produced a row this stays null.
    return {
      recentOrders: rows.map((r) => ({ id: r.id, totalCents: r.totalCents, createdAt: r.createdAt })),
      revenueCents,
      lowStock,
      topCoffee: null,
    };
  } catch {
    return { recentOrders: [], revenueCents: 0, lowStock, topCoffee: null };
  }
}
